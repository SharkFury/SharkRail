# Contributing to SharkRail

Thank you for your interest in improving SharkRail.

## How to contribute

1. Open an issue first for API or behavior changes.
2. Keep all PRs focused on one feature or one fix set.
3. Add or update tests for every new behavior.
4. Update documentation when user-facing behavior changes.

## Development rules

- English is the default language for code and docs.
- Feature changes should include unit tests.
- CLI and protocol behavior should be covered by tests when changed.

## Commit discipline

Each completed feature should be committed separately so release history remains clear.

## Review checklist

- Lifecycle semantics are explicit
- Errors and timeouts have tests
- Backward compatibility is described in docs
- No new hard dependency without explicit review
